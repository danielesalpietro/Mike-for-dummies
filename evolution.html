Mike for Dummies

The 60-second Dockerized version — zero host dependencies

Goal

Make the upstream project runnable by anyone with Docker, without installing Node.js, LibreOffice, or any other runtime on the host. An interactive Python wizard (setup.py) generates both .env files automatically.

Changes from upstream
  • ＋docker-compose.yml — single file spins up frontend and backend containers.
  • ＋setup.py — interactive wizard; validates API keys, fixes URL formatting, writes .env files with automatic backups.
  • ＋Dockerfiles — Node.js and LibreOffice are bundled inside the images; the host stays clean.
  • →External services (Supabase hosted, Cloudflare R2, LLM keys) are still required — this edition only removes the host-runtime dependency.

Mike Self-Hosted Full Stack

No Supabase cloud, no Cloudflare R2 — everything runs inside Docker Compose

Goal

Replace every hosted cloud service with a self-hosted equivalent running as a Docker container on the local machine. Legal documents never leave the host. Only LLM API keys remain external.

Cloud services eliminated
Upstream (cloud)Replacement (local Docker)
Supabase Auth (hosted)GoTrue — self-hosted identity server
Supabase PostgREST (hosted)PostgREST + PostgreSQL 15
Supabase DB (hosted)PostgreSQL 15-alpine
Cloudflare R2MinIO — S3-compatible object storage
Changes from v1
  • ＋supabase-db — PostgreSQL 15-alpine container with bind-mount data directory; data persists across rebuilds.
  • ＋supabase-auth — GoTrue container wired to the local DB; handles signup, login, JWT issuance.
  • ＋supabase-rest — PostgREST container; auto-generates REST API from the PostgreSQL schema with RLS enforcement.
  • ＋supabase-api — nginx gateway routing /auth/v1/* → GoTrue and /rest/v1/* → PostgREST, replicating the Supabase API surface.
  • ＋minio + minio-setup — S3-compatible storage; bucket created automatically on first boot.
  • ＋db-migrate — one-shot container runs 000_one_shot_schema.sql after GoTrue finishes its own migrations.
  • ~backend/src/lib/storage.ts — forcePathStyle: true added for MinIO path-style S3 compatibility.
  • ~supabase nginx config — CORS allow-list extended with x-supabase-api-version and apikey headers required by the self-hosted client.
  • ~.env.docker — pre-configured JWT secret, ANON_KEY, SERVICE_ROLE_KEY, MinIO credentials; safe defaults for local use.
  • →Application code (frontend, backend, document processing, LLM calls) is unchanged from upstream.

Mike on MicroCloud

No Docker on the host — each service runs in a native Ubuntu LXD container on private infrastructure

Goal

Move from Docker Compose to a production-grade private infrastructure stack. Each microservice runs in a dedicated LXD container provisioned via cloud-init. MicroCloud provides the network fabric (fan overlay) and storage (ZFS / MicroCeph). No Docker daemon required on the host.

Tested stack
Windows 10/11 Pro └── VMware Workstation └── Ubuntu 24.04 LTS (VM) └── MicroCloud + LXD ├── Container: mike-backend (Node.js + Express, :3001) └── Container: mike-frontend (Next.js, :3000)
Changes from v1 / v2
  • ＋lxd/profiles/common.yaml — base LXD profile (NIC on lxdfan0, ZFS root on local pool).
  • ＋lxd/profiles/backend.yaml / frontend.yaml — per-service LXD profiles with resource limits and cloud-init injection.
  • ＋lxd/cloud-init/backend.yaml / frontend.yaml — declarative provisioning: installs Node.js, clones the repo, copies .env, starts the service via systemd.
  • ＋lxd/launch.sh — single script to create, profile, and start one or both containers; idempotent re-runs.
  • ~Deployment model — Docker Compose is replaced by LXD containers; the docker-compose.yml is kept for the local-development mode only.
  • ~Networking — services are addressed by real LXD container IPs on the fan network, not Docker bridge aliases; FRONTEND_URL and NEXT_PUBLIC_API_BASE_URL must use the host IP.
  • →External services (Supabase hosted, Cloudflare R2) are still used in the v3 branch — the self-hosted Supabase stack from v2 can be layered in separately.
  • →High-availability and storage replication are provided by MicroCeph (Ceph over MicroCloud); not wired into the app itself but available at the infrastructure layer.
